3 · Installazione e avvio passo passo

  1. Estrai lo ZIP in una cartella, ad esempio C:\progetti\NABOAT-portale (oppure ~/progetti su Mac/Linux).
  2. Apri il terminale nella cartella dell'app
    cd NABOAT-portale/naboat-gestionale
  3. Crea il file dei segreti locali
    copia .env.local.example in .env.local:
    # Windows (PowerShell)
Copy-Item .env.local.example .env.local
# Mac/Linux
cp .env.local.example .env.local
    Anche .env.example → .env serve per i container:
    Copy-Item .env.example .env   # Mac/Linux: cp .env.example .env
  4. Avvia Docker Desktop e attendi che sia "running" (icona della balena).
  5. Avvia database e cache
    docker compose up -d db redis
    Attendi ~10 secondi. Le porte usate sono 5434 e 6380 per evitare conflitti con altri programmi.
  6. Installa le librerie
    npm install
  7. Prepara il database
    npx prisma migrate deploy
  8. Crea l'amministratore e i dati demo
    npm run db:seed        # crea il superadmin
npm run db:seed:test   # crea i dati dimostrativi (barche, prenotazioni, clienti)
  9. Avvia l'applicazione
    npm run dev
    Apri il browser su http://localhost:3000. Per fermarla: Ctrl + C.

4 · Usare il database del pacchetto

Il file database/naboat-demo.sql è una copia completa del database con dentro i dati demo. Per ripristinarlo (attenzione: sovrascrive i dati attuali):

# Windows (PowerShell) — dalla cartella naboat-gestionale
Get-Content ..\database\naboat-demo.sql | docker compose exec -T db psql -U naboat -d naboat

# Mac/Linux
cat ../database/naboat-demo.sql | docker compose exec -T db psql -U naboat -d naboat

In alternativa, se preferisci partire da un database vuoto, salta questo passaggio: npm run db:seed e npm run db:seed:test bastano a popolare tutto.

Se hai cambiato la password nel file .env, sostituisci -U naboat con il tuo utente e aggiungi la password quando richiesta.

5 · Modificare il portale con OpenCode

OpenCode è un assistente che lavora direttamente sui file del progetto: gli si parla in italiano e lui legge, propone e applica le modifiche.

  1. Apri il terminale nella cartella dell'app
    cd naboat-gestionale
  2. Lancia OpenCode
    opencode
  3. Fai analizzare il progetto
    Scrivi /init: OpenCode legge la struttura. Nel pacchetto c'è già un file AGENTS.md pronto con le regole del progetto, quindi conosce già le convenzioni.
  4. Chiedi quello che ti serve
    Esempi che funzionano bene:
    • «Spiegami come funziona la gestione delle prenotazioni in src/app/api/v1/bookings/route.ts»
    • «Aggiungi un campo "caparra" alle prenotazioni, con campo nel modulo e nel database»
    • «Rendi la pagina Oggi più leggibile su telefono»
    • «Aggiungi una nuova pagina Statistiche con il numero di uscite per barca»
  5. Modalità Pianificazione
    Premi Tab per passare in modalità "plan": OpenCode propone come farebbe la modifica senza toccare nulla. Rileggi, correggi, poi torna in modalità normale e digli di procedere.
  6. Se qualcosa non va
    /undo annulla l'ultima modifica, /redo la ripristina.
  7. Verifica sempre
    Dopo una modifica chiedi: «esegui npm run build e correggi eventuali errori».
Importante: chiedi a OpenCode di lavorare sempre con criterio e di non rimuovere i controlli di sicurezza. Nel file AGENTS.md sono elencate le regole da rispettare (es. ogni API deve controllare l'azienda di appartenenza).

6 · Abbonarsi a OpenCode Go e usare DeepSeek V4.1 Flash

Per usare modelli AI potenti senza gestire chiavi di più fornitori, OpenCode offre OpenCode Go: un abbonamento da 10 $/mese che dà accesso a un elenco curato di modelli open per il coding. Tra questi c'è DeepSeek V4.1 Flash.

Come attivarlo

  1. Apri OpenCode nel terminale (comando opencode).
  2. Scrivi /connect e seleziona OpenCode Go.
  3. Ti apre la pagina opencode.ai/auth: fai l'accesso, aggiungi i dati di pagamento e abbonati a Go.
  4. Copia la chiave API che ti viene mostrata e incollala nel terminale quando richiesto.
  5. Scrivi /models e scegli DeepSeek V4.1 Flash.
Quanto si usa con 10 $/mese? Il piano Go include un budget di utilizzo mensile per modello. Con DeepSeek V4.1 Flash si parla di decine di migliaia di richieste stimate al mese — più che sufficiente per lavorare su un progetto come questo. Puoi controllare il consumo dalla console su opencode.ai/auth.

Impostarlo come modello predefinito (opzionale)

Per non doverlo scegliere ogni volta, crea nella cartella del progetto il file opencode.json:

{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode-go/deepseek-v4.1-flash"
}

Il formato dell'identificativo è opencode-go/<nome-modello>. Se non sei sicuro del nome esatto, usa /models: OpenCode scrive da solo la configurazione corretta.

Note utili

  • L'abbonamento Go è opzionale: OpenCode funziona anche con altri fornitori, senza vincoli.
  • Serve una connessione internet: l'assistente lavora tramite il servizio online.
  • Il codice del portale resta sul tuo PC: viene inviato al modello solo ciò che serve per rispondere alle tue richieste.
  • Con Go puoi anche usare modelli gratuiti quando raggiungi il limite mensile.

7 · Problemi comuni

Messaggio / sintomoCausa e soluzione
failed to connect to the docker APIDocker Desktop non è avviato. Apri l'app e attendi l'icona "running".
P1001: Can't reach database serverIl database non è pronto: esegui docker compose up -d db redis e attendi 10 secondi.
AUTH_SECRET mancante o troppo cortoManca .env.local: copialo da .env.local.example.
Porta 5434 già occupataUn altro progetto usa quella porta: modifica docker-compose.override.yml (es. 5435) e aggiorna di conseguenza DATABASE_URL in .env.local.
Non entro: "Non autenticato"La sessione è scaduta o hai riavviato il server: rifai il login.
npm run dev non parteEsegui npm install e controlla di avere Node.js 20+ (node -v).
Voglio ripartire da zerodocker compose down -v poi docker compose up -d db redis, npx prisma migrate deploy, npm run db:seed.
Comandi che tornano sempre utili 
docker compose up -d db redis   # avvia database e cache
npm run dev                     # avvia il portale (http://localhost:3000)
npm run build                   # verifica che tutto compili
node scripts/smoke-test.mjs http://localhost:3000   # 27 test automatici
docker compose down             # spegne i container (i dati restano)
